# CarX Deck Tools

Приложение для Windows (Avalonia, .NET 10), которое управляет Steam Deck по Wi‑Fi или проводу (USB‑C хаб с Ethernet). Заливает и запускает тестовые Linux-билды Unity и помогает подключить к ним отладчик Rider.

Исследование и план — в [RESEARCH.md](RESEARCH.md).

## Что умеет

| Вкладка | Возможности |
|---|---|
| **Steam Deck** (верхняя панель) | Поиск в сети (mDNS), добавление по IP, сопряжение через Developer Mode (протокол SteamOS Devkit), установка ключа по паролю, подключение по SSH |
| **Экран** | Экран Deck на ПК с управлением мышью, клавиатурой и геймпадом: Sunshine на Deck (установка, запуск, сопряжение в одно нажатие) и Moonlight на ПК. Скриншот Deck одной кнопкой: файл на ПК и картинка в буфере обмена |
| **Устройство** | Версия SteamOS, режим (Game Mode / рабочий стол), батарея, температуры, память, диск. Переключение Game Mode ↔ рабочий стол, перезапуск Steam, перезагрузка и выключение, SSH-терминал (Windows Terminal), включение CEF-отладки Steam |
| **Билды** | Профили билдов, заливка с дельтой (повторно уходят только изменённые файлы), ярлык «Devkit Game» в библиотеке Steam, запуск и остановка, живой `Player.log` с подсветкой ошибок и предупреждений, поиском и фильтром. Заливка и запуск по команде из Unity |
| **Отладка** | Адрес и порт отладчика Unity-плеера из `Player.log`, повтор анонса плеера в сети ПК, чтобы его видели Rider и Unity Editor. Запись Unity Profiler в файл на Deck с первого кадра и скачивание записи. Оверлей MangoHud и замеры производительности Deck в CSV с итогами (средний FPS, 1% и 0,1% low, загрузка, температуры, мощность) |
| **Файлы** | Обзор Deck по SFTP, загрузка файлов и папок (кнопками или перетаскиванием из Проводника), скачивание, создание, переименование, удаление. Папки обмена с рабочим столом Deck |
| **Консоль** | Разовые команды на Deck |

## Первый запуск

1. На Deck: **Настройки → Система → Enable Developer Mode**, затем **Настройки → Developer → Pair new host**.
2. В приложении: **Найти в сети** (или **Добавить…** по IP), затем **Сопрячь (Developer Mode)** и подтвердить запрос на Deck.
3. **Подключить**.

Если Deck уже сопряжён официальным SteamOS Devkit Client, его ключ подхватывается сам: достаточно добавить Deck и нажать «Подключить».

Без Developer Mode: в Konsole на Deck задать пароль (`passwd`), включить SSH (`sudo systemctl enable --now sshd`) и нажать **Ключ по паролю…**. Пароль не сохраняется.

Ключ приложения лежит в `%APPDATA%\SteamdeckViewer\keys\deck_rsa`, настройки — в `%APPDATA%\SteamdeckViewer\settings.json`.

## Удалённый экран

1. Установить на ПК [Moonlight](https://moonlight-stream.org/).
2. Вкладка **Экран** → **Установить…** и пароль пользователя Deck. Пароль нужен один раз и не сохраняется.
3. **Открыть экран Deck**: приложение запускает Sunshine, при первом запуске само сопрягает Moonlight и открывает окно стрима.

Sunshine (flatpak `dev.lizardbyte.app.Sunshine` в system-установке) работает в одном из двух вариантов с общими настройками и сопряжениями:
- **Game Mode** снимается только KMS-захватом, а он требует root. Поэтому, как в плагине decky-sunshine, служба `sdv-sunshine.service` запускает Sunshine от root с setuid-копией `bwrap`. Правило polkit разрешает пользователю Deck запускать и останавливать её без пароля.
- **Рабочий стол** KMS-захват отдаёт повёрнутым на 90°. Поэтому здесь Sunshine работает пользовательской службой `sdv-sunshine-desktop.service` и снимает экран через KDE (xdg-desktop-portal). Разрешение KDE выдаётся заранее, подтверждать на Deck ничего не нужно.

Приложение запускает вариант под текущий режим Deck. Если режим сменился во время стрима, приложение само переключает Sunshine и открывает Moonlight заново.

Выход из программы заканчивает трансляцию: окно Moonlight, открытое программой, закрывается, а Sunshine на Deck останавливается (галка **Останавливать Sunshine на Deck при выходе из программы**, включена по умолчанию). Остановку программа ждёт не дольше 5 секунд, а при выключении Windows не ждёт совсем. Moonlight, запущенный вручную, программа не трогает.

Мышь на рабочем столе абсолютная: курсор ПК совпадает с курсором Deck. В Game Mode она относительная, как в играх. Щёлкните в окно стрима, чтобы захватить её, а **Ctrl+Alt+Shift+Z** её отпускает. Абсолютную мышь Sunshine gamescope пока не понимает: курсор застревает в углу ([ValveSoftware/gamescope#2458](https://github.com/ValveSoftware/gamescope/issues/2458)).

**Сделать скриншот** (вкладка «Экран», то же — **Скриншот** на вкладке «Билды») снимает экран Deck без Moonlight: файл `SteamDeck_<дата>_<время>.png` ложится в `Рабочий стол\Steam Deck\Скриншоты` (рядом с папками обмена), а картинка — в буфер обмена, чтобы сразу вставить её в задачу или чат. В Game Mode снимает сам gamescope (`gamescopectl screenshot`): игра с оверлеями MangoHud и Steam так, как на экране. На рабочем столе снимает `spectacle`.

После переустановки у Sunshine новые сертификат и uuid, а Moonlight помнит Deck по адресу со старым uuid: такие ответы он игнорирует как чужие, ждёт до таймаута и не сопрягается. Поэтому перед сопряжением и стримом программа спрашивает у Sunshine его uuid (`/serverinfo`) и правит настройки Moonlight (`HKCU\Software\Moonlight Game Streaming Project\Moonlight\hosts`): запись с адресом Deck, его именем и чужим uuid удаляет, а у записи с другим именем (адрес раньше был у другого ПК) только стирает этот адрес. Moonlight при этом должен быть закрыт — иначе программа попросит его закрыть.

Установка, сделанная до появления второго варианта, обновляется кнопкой **Установить…**, сопряжение сохраняется. Подробности в разделе 11 [RESEARCH.md](RESEARCH.md). Кнопка **Удалить…** убирает всё перечисленное.

## Папки обмена

Moonlight не передаёт файлы, поэтому перетащить файл из окна стрима в Проводник нельзя. Вместо этого, пока приложение подключено к Deck, работают папки обмена (вкладка **Файлы**, блок «Папки обмена»):

| Откуда | Куда |
|---|---|
| «На ПК» на рабочем столе Deck | `Рабочий стол\Steam Deck\С Deck` на ПК |
| `Рабочий стол\Steam Deck\На Deck` на ПК | «С ПК» на рабочем столе Deck |

- В стриме перетащите файл или папку в «На ПК» в Dolphin или на рабочем столе. Через пару секунд они появятся на ПК.
- Файл передаётся, когда его размер и время изменения не менялись между двумя проверками, поэтому недокопированный файл не уйдёт.
- Удаление не передаётся. Изменённый файл передаётся заново и перезаписывает копию.
- Что уже передано, приложение помнит отдельно для каждого Deck (`%APPDATA%\SteamdeckViewer\exchange`), поэтому после перезапуска удалённое на другой стороне не вернётся.
- Папку на ПК можно сменить кнопкой **Папка на ПК…**, а обмен выключить флажком.

## VPN

Клиенты на WireGuard/AmneziaWG (в том числе AmneziaVPN) при маршрутизации всего трафика включают kill switch. Он блокирует всю локальную сеть: ping показывает «Общий сбой», а приложение пишет, что соединение заблокировано VPN. Чтобы работать с Deck, не выключая VPN, это настраивается один раз:

- **AmneziaVPN**, проверенный вариант: «Раздельное туннелирование приложений» → добавить `CarXDeckTools.exe` и `C:\Windows\System32\OpenSSH\ssh.exe` (для SSH-терминала). Если Rider подключается к игре при включённом VPN, его тоже нужно исключить, либо исключить подсеть, как в следующем пункте.
- **AmneziaVPN**, исключение по адресам: «Раздельное туннелирование сайтов» → режим «Адреса из списка не должны открываться через VPN» → добавить подсеть офиса (например, `10.23.0.0/16`).
- **Конфиг WireGuard/AmneziaWG напрямую**: в `AllowedIPs` заменить `0.0.0.0/0` на `0.0.0.0/1, 128.0.0.0/1`. Весь интернет по-прежнему идёт через VPN, но kill switch не включается ([netquirk.md](https://github.com/amnezia-vpn/amneziawg-windows-client/blob/master/docs/netquirk.md)).

## Тестовый билд CarX Street

1. **Build/Street Build Settings**: платформа Linux, Development и Script Debugging (для Rider), EAC выключен.
2. Вкладка **Билды**: указать папку билда (`CarX_Street.x86_64` подставится сам) и нажать **Залить и запустить**.
3. Игра появится в библиотеке Steam как «Devkit Game: CarX_Street» и запустится в Game Mode.

Из Unity то же одним действием: в **Build/Street Build Settings** при платформе Linux включить **Run on Steam Deck** и нажать **BUILD** — после сборки программа сама зальёт изменённые файлы и запустит игру. **Run Last Build on Steam Deck** там же — то же без сборки. Код — `Assets/_PC/Scripts/Editor/SteamDeckDeploy.cs` в проекте игры.

Под капотом это запуск `CarXDeckTools.exe --deploy "<папка билда>" --run`: если программа уже открыта, команда уходит в её окно по именованному каналу. Папка должна совпадать с папкой одного из профилей. Путь к exe программа при каждом запуске записывает в `%APPDATA%\SteamdeckViewer\app-path.txt` — так его находит Unity.

Удаление лишних файлов на Deck включено по умолчанию: проверка целостности игры (`player_layout.bundle`, ошибка E29) не терпит старых `.so`/`.dll` в папке билда.

Галка профиля **Проверять целостность по player_layout.bundle** (только для проекта Street PC, по умолчанию выключена) повторяет эту проверку на Deck после каждой заливки: бинарники в папке игры сверяются с `player_layout.bundle` из сборки на ПК. Если что-то не сходится, игра не запускается, а программа показывает лишние, недостающие и изменённые файлы. Игра в таком случае остановилась бы на E29 (на экране E3239-000), не оставив следа в `Player.log`. С включённой галкой появляется и кнопка **Проверить целостность**.

`Player.log` справа на вкладке «Билды»: ошибки и исключения красные, предупреждения жёлтые, стек вызовов приглушён, сообщения самой программы синие. Тип сообщения Unity пишет только в стеке (`UnityEngine.Debug:LogWarning(…)`), поэтому сообщение без стека остаётся обычным, если в нём нет явных признаков вроде `ERROR:` или `[error]`. Поиск — **Ctrl+F**, Enter/Shift+Enter или F3/Shift+F3 по совпадениям; фильтр оставляет только предупреждения и ошибки или только ошибки; кнопки **Ошибки: N ↓** и **Предупреждения: N ↓** переходят к следующей такой записи после курсора. В окне держатся последние 20 000 строк.

**Отчёт для задачи** (вкладка «Билды») собирает один zip в `Рабочий стол\Steam Deck\Отчёты` и показывает его в Проводнике — остаётся перетащить в задачу. Внутри `Player.log` и `Player-prev.log`, скриншот экрана Deck, последний замер MangoHud и `report.txt`: версия сборки и Unity из лога, когда сборка собрана на ПК и залита на Deck, запущена ли игра, число ошибок и предупреждений в логе со строками ошибок, состояние Deck (SteamOS, версия клиента Steam, режим, батарея, температуры, память), итоги MangoHud и что собрать не удалось.

Отладка: Rider → **Run → Attach to Unity Process** → плеер из списка или **Add player address manually** с адресом с вкладки «Отладка». Анти-отладка `DD.cs` закрывает игру при подключённом отладчике, если в билде нет `DEV_BUILD` или `DISABLE_CHECK_DEFENCE`.

Unity Profiler: вживую — Window → Analysis → Profiler → **Attach to Player** → плеер Deck (или `<Enter IP>` с IP Deck). Запись без редактора — галка **Записывать профиль в файл на Deck** на вкладке «Отладка»: игра стартует с `-profiler-enable -profiler-log-file` и пишет `.raw` в `~/.local/share/carx-deck-tools/profiler/<id>` с первого кадра, включая загрузку, а сеть на замеры не влияет. Кнопка **Скачать последнюю запись** сохраняет файл на ПК, открыть его — Profiler → **Load**. Нужна Development-сборка, залитая через программу и запущенная её кнопками или из Unity: на игры из магазина Steam и другие ярлыки в библиотеке Deck запись не действует.

Производительность Deck: галки **Показывать оверлей MangoHud** и **Записывать замеры в CSV** на вкладке «Отладка». Программа передаёт игре `MANGOHUD=1` и `MANGOHUD_CONFIG` на этот запуск (MangoHud входит в SteamOS, Development-сборка не нужна). Галки действуют на билд, залитый через программу и запущенный её кнопками или из Unity. Для игры из магазина Steam (AppID из поля «Steam AppID» профиля) кнопка **Включить для игры из Steam** записывает в её параметры запуска `env MANGOHUD=1 MANGOHUD_CONFIG=… %command%` по тем же галкам, **Выключить для игры из Steam** их очищает. Пишет она через CEF-отладку Steam (`SteamClient.Apps.SetAppLaunchOptions` во вкладке SharedJSContext, порт 8080 на Deck через SSH-туннель); без отладки строка копируется в буфер обмена для ручной вставки. Параметры запуска заменяются целиком, прежние программа выводит в окно Player.log. Steam в Game Mode вычищает `MANGOHUD*` из окружения игры (оверлей у него свой, mangoapp), поэтому при запуске через Steam переменные ставит обёртка `carx-deck-tools-launch.sh` в папке игры: Steam запускает её, она — игру. Проверке целостности она не мешает, следующая заливка её удаляет. Оверлей показывает FPS, время кадра с графиком, загрузку, температуры и мощность CPU/GPU, память и батарею. Замеры пишутся по кадру в `~/.local/share/carx-deck-tools/mangohud/<id>`; **Скачать последний замер** сохраняет CSV на ПК и показывает итоги: средний FPS, 1% и 0,1% low, время кадра, загрузку, температуры, мощность и память.

## Сборка и запуск

```bash
dotnet run --project src/SteamdeckViewer
```

### Сборка релиза

Двойной клик по `publish.bat` — откроется меню:

```
[1] собрать                    [3] проверить компиляцию без публикации
[2] версия программы           [4] открыть папку publish
                               [5] очистить папку publish
```

Сборка попадает в `publish\win-x64`: один самодостаточный `CarXDeckTools.exe` (.NET ставить не нужно). Пункт `[2]` правит константу `AppVersionText` в `src/SteamdeckViewer/AppInfo.cs` (версия в заголовке окна): скрипт показывает текущее значение, предлагает следующее и ждёт подтверждения. Коммитить изменение нужно руками.

Без меню (для CI и скриптов):

```
publish.bat nopause
```

Либо вручную:

```bash
dotnet publish src/SteamdeckViewer -c Release -r win-x64 -o publish/win-x64
```

Тесты (скрипты для Deck прогоняются в WSL, без WSL эти тесты пропускаются):

```bash
dotnet test
```

## Обновление у коллег

О новой версии программа узнаёт из документа, ссылка на который зашита в `AppInfo.UpdateUrl`: Google Doc с доступом «Все, у кого есть ссылка» (подойдёт и любой адрес, по которому отдаётся такой текст). В нём три поля:

```
version: 1.0.1
url: https://drive.google.com/file/d/…/view
message: Что нового — эта строка и все следующие
```

Программа читает документ при запуске и раз в 3 часа. Если `version` новее её собственной, появляется окно «Нужно обновиться» с текстом из `message`: **OK** открывает `url` в браузере, **Позже** откладывает напоминание до следующего запуска. Проверить вручную — **Справка → Проверить обновления**.

Выпуск новой версии:
1. `publish.bat` → `[2]` поднять версию, `[1]` собрать.
2. Загрузить `publish\win-x64\CarXDeckTools.exe` на Google Drive (доступ «Все, у кого есть ссылка»). Если заменять файл через «Управление версиями», ссылка не меняется.
3. В документе поменять `version` (и `url`, если файл новый) и написать `message`.

## Устройство проекта

- `src/SteamdeckViewer.Core` — всё без UI:
  - протокол devkit (`DevkitService`, `DeckDiscovery`, `DeckKeys`);
  - SSH/SFTP (`DeckConnection`);
  - заливка tar-потоком (`FolderSync`);
  - ярлыки и запуск через `~/.steam/steam.pipe` (`DevkitGames`);
  - разбор `Player.log` и повтор анонса для Rider (`UnityPlayer`);
  - команды из Unity и их передача открытой программе (`ExternalCommand`);
  - сверка файлов на Deck с индексом целостности CarX Street (`PlayerLayout`);
  - запись Unity Profiler в файл на Deck (`ProfilerCapture`);
  - оверлей и замеры MangoHud с подсчётом итогов (`MangoHudCapture`);
  - разбивка `Player.log` на записи и их уровни для подсветки (`PlayerLogModel`);
  - скриншот экрана Deck (`DeckScreenshot`);
  - JS в интерфейсе Steam через CEF-отладку и SSH-туннель (`SteamCef`);
  - чистка устаревших записей Deck в настройках Moonlight (`MoonlightHosts`);
  - объявление о новой версии программы (`AppUpdate`);
  - архив с логами, скриншотом и состоянием Deck для задачи (`BugReport`).
- `src/SteamdeckViewer` — окно Avalonia, разметка на C# (без XAML), по одной partial-части на вкладку.
- `tests/SteamdeckViewer.Tests` — xUnit: фильтры, разбор логов, формат ключей против `ssh-keygen`, протокол devkit на поддельной службе, скрипты для Deck и tar в Linux (WSL).
